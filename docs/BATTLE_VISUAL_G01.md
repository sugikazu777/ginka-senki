# 銀花戦記 — 戦闘画面のビジュアル最優先計画 G01

更新日: 2026-10-18  
状態: 開発方針（PCファーストへ更新。新構成は実装・実機検証未着手）

## 目的

参考画像 `IMG_4655.jpeg` に示された、美麗なファンタジー戦術SLGの画面密度・表現・操作感を、**PC・16:9横長画面**で最短の実装サイクルにより実現する。参照画像は縦構図なので、無理に引き伸ばさず、構図・配置をPC向けに再設計する。

- **戦闘画面**: 高品質な固定視点2.5D戦場＋精細な2Dキャラクター＋戦術的に判読できるHUD。**エンジンは手段として選定し、Unityには固定しない。**
- **街探索**: 現行 `town/index.html` をHTMLプロトタイプとして維持する。今回は街に機能追加しない。
- **正本**: 既存 `index.html` の P05.4 を破壊・上書きしない。既存の移動・攻撃・EXP・固定成長・ミッションを仕様参照として保持。

## ビジュアル準拠項目（優先順）

1. **1920×1080の16:9横長PC画面**、固定の浅い2.5D、菱形🔶グリッド、高さ0/1/2が自然に判別できる。
2. 植生・石造り・川・橋を精緻な描画済みテクスチャ・レイヤーで表現し、地形面と側面を整合させる。
3. キャラクターは小さな3Dモデルではなく、同一の基準デザインから制作した透明背景2Dスプライト。個人識別可能な顔・髪・衣装・シルエット、待機と移動。
4. HPバー・数値をユニットの足元付近に明瞭に描き、選択時は左側の味方ステータスと右側の敵情報を表示。
5. 青＝移動可能、赤＝攻撃可能／危険、選択マス明確化。いずれも地形より見やすい前面表示。
6. 画面上部に章／ターン／勝利条件。**左右パネルも使用**できるPC向けHUDとし、移動・攻撃・能力・待機はキーボードショートカットまたはクリックで直感的に操作できるようにする。
7. 戦闘ルールは複雑化しない。**参考画像内の地形防御・回避補正は再現しない**（現行合意は地形・高さの戦闘補正なし）。

## 絵を作る手段と実行時構成

- **オフラインで高品質に描く**: 背景を高品質画像から分離し、地面・手前の遮蔽物・キャラクター・光／エフェクト・HUDを別素材にする。
- **ランタイムは軽量に**: 固定視点を活かし、描画済み地形を基本とし、論理マス／高さ／通行可否は別データで管理。
- スクリーンショットを丸ごと背景にすると、焼き込まれたキャラクターや射程が残り、インタラクションに破綻が出る。**一枚絵の貼り込みを完成扱いしない**。
- リリアなどのキャラクターは基準素材・統一制作フローを設け、スプライト差分でidentityを保つ。
- **まずPixiJS v8＋TypeScriptを第一候補**に、ブラウザ上で参考画像に近い表現を実装する。GPU描画はWebGLを優先。現行P05.4のJS戦術ロジックは移植・分離して再利用する。
- **Phaser 3/4を第二候補**にする。標準2DゲームAPIやPhaser Editor v5のMCPを活用したい場合に比較する。Phaser Editor v5のMCPはベータ／契約条件を要確認。
- **Unityを第三候補**とし、真の3D地形編集や複数視点が必要になったときに再検討する。公式Unity MCPはAI beta（Unity 6、Cloud連携、AI trial/契約など条件あり）。
- **Godotは比較対象**として、CLIによるヘッドレス編集・テスト・ビルドとコミュニティMCPを評価する。
- PCブラウザのロード時間、ピークメモリ、FPSを実測する。スマホ最適化は当面合格条件にしない。

## 先行する3つの成果物

### G01-A: 見栄えの基準スクリーン（機能は限定）
**1920×1080 / 16:9横長画面**で、地形・リリア・敵・HP・HUD・範囲表示を参考画像と比較する。縦参照画面の構図をそのまま流用せず、PC上で見やすいレイアウトに再構成する。  
**合格条件**: 美麗さ・キャラクターの見え方・グリッドの視認性について、静止画比較で改善箇所を明確にできる。

### G01-B: 操作可能な小規模戦場
固定カメラ、移動・射程、**マウスホバーで簡易情報／クリックで選択・詳細**、移動先選択、攻撃・HP変化、ホイール拡大・ドラッグ／画面端スクロール。  
**合格条件**: 見た目を維持しながらPC上でマウス選択の誤認なく操作できる。

### G01-C: P05.4機能の統合
経験値・固定成長・フェイズ進行・敵AI・3つの勝利条件を移植／統合。  
**合格条件**: 既存P05.4でできた主要行動が失われず、一章をクリアできる。

## UI基準変更（2026-10-18確定）：PCファースト

**この章は上記の旧モバイル前提の記述より優先する。**

- **ゲーム全体のUI設計基準をPC・16:9横長へ変更。** 1920×1080をデザイン基準とし、ブラウザの可変ウィンドウサイズと高解像度モニターへのスケールを考慮する。
- スマホ9:16前提の画面構成、ピンチ操作、画面下部に全機能を詰め込む制約は**今後の新規画面の必須要件から外す**。現行HTML版のスマホ機能は削除せず、そのまま保存する。
- 戦闘時は広い菱形盤面が主役。左右の余白は味方情報、敵ステータス、行動順、選択コマンドなどに活用可能。マップ表示範囲とキャラクター視認性を実機で調整する。
- **カメラの回転・俯瞰モードへの切り替えは導入しない。** 固定カメラで遮蔽・高低差を読める設計を維持。
- **マウス**：ホバーで射程・HP等の簡易情報、クリックで選択・確定、ドラッグでスクロール、ホイールでズーム。**キーボード**：行動ショートカットは補助として検討（マウスだけで完結可能）。
- 街探索は別系統のHTML試作として継続し、街探索のPC版UI再構成は戦闘画面の品質検証後に行う。
- 技術選定はUnityを必須とせず、画質・制作時間・エージェントがAPI/MCPで制御できるか・自動検証の容易さを重視する。
- 次の成果物は**PC用16:9高品質戦闘画面の静止画＋操作可能な小規模戦場**。参考画像の再現性と操作感を独立に検証。

## 制作素材の基本方針（2026-10-18 確定）

- **素材類は基本的にGPTの画像生成で制作する。** ゲームエンジンは素材生成を担わず、生成済みアートの合成・表示・入力・戦闘ロジック・アニメーションを担う。
- **最速の画質到達を優先する初期方式**: 16:9の固定カメラ戦場を「ユニット／HP／攻撃範囲／HUD／戦闘エフェクトなし」の高精細な美術背景として生成し、論理グリッド・高さ0/1/2・通行可否を別データで対応付ける。人物・グリッド・範囲・HP・UIは描画レイヤーを分ける。背景一枚絵に人物やUIが焼き込まれた状態をプレイアブル実装の完成としない。
- **キャラクターの同一性が最重要**: 採用したキャラクターシートを基準画像とする。単発の独立生成で多数の角度・表情・歩行コマを作るとidentity driftが起こるため、参照固定・編集・少数の差分・共通の元絵からの切り出しを優先。人物ごとに基準画像、透明スプライト、表示倍率、足元アンカー、アニメーション差分を明示的に管理する。
- **地形の整合性**: ピクセル基準の菱形セル境界と3階層の段差、キャラクターの足元位置、前面遮蔽マスク、敵範囲のオーバーレイをコードで座標管理。複数マスを個別生成して継ぎ目を発生させることは避け、まずマップ全体の美麗な背景＋座標別描画レイヤーで品質検証する。
- **UIの文字・数値・インタラクションはコード側で描画**する。生成画像に日本語テキストやHP値を焼き込まない。文字の正確さと動的更新、操作性を保証する。
- **GPT画像生成の対話操作とAPI自動生成は別**: エージェントでの大量生成・加工・再試行には、実際に利用可能な画像生成APIとアセット処理パイプラインの確認・接続が必要。MCPの有無だけでなく、一括生成、編集、マスク処理、検収、コスト、再現性を評価する。
- **素材台帳の推奨キー**: asset_id、用途、基準画像/バージョン、プロンプト、生成/編集日時、解像度、透過有無、ファイルパス、採否、ゲーム側の表示座標／サイズ。未承認画像を参照デザインの正本にしない。
- **素材品質の第一マイルストーン**: 参考画像に忠実な「背景のみ」「リリア単体」「敵単体」「戦術HUDなし」と「全部合成」の画像を作り、16:9で差分比較。これを通過してから可動化する。
