# 銀花戦記 — 戦闘画面のビジュアル最優先計画 G01

更新日: 2026-10-18  
状態: 開発方針（実装・実機検証は未着手）

## 目的

参考画像 `IMG_4655.jpeg` に示された、美麗なファンタジー戦術SLGの画面密度・表現・操作感を、最短の実装サイクルで実現する。

- **戦闘画面**: 高品質な固定視点2.5D戦場＋精細な2Dキャラクター＋戦術的に判読できるHUD。必要ならUnityへ移行する。
- **街探索**: 現行 `town/index.html` をHTMLプロトタイプとして維持する。今回は街に機能追加しない。
- **正本**: 既存 `index.html` の P05.4 を破壊・上書きしない。既存の移動・攻撃・EXP・固定成長・ミッションを仕様参照として保持。

## ビジュアル準拠項目（優先順）

1. 9:16縦持ち、固定の浅い2.5D、菱形🔶グリッド、高さ0/1/2が自然に判別できる。
2. 植生・石造り・川・橋を精緻な描画済みテクスチャ・レイヤーで表現し、地形面と側面を整合させる。
3. キャラクターは小さな3Dモデルではなく、同一の基準デザインから制作した透明背景2Dスプライト。個人識別可能な顔・髪・衣装・シルエット、待機と移動。
4. HPバー・数値をユニットの足元付近に明瞭に描き、選択時は左側の味方ステータスと右側の敵情報を表示。
5. 青＝移動可能、赤＝攻撃可能／危険、選択マス明確化。いずれも地形より見やすい前面表示。
6. 画面上部に章／ターン／勝利条件、下部に大きな移動・攻撃・能力・待機ボタンを配置。
7. 戦闘ルールは複雑化しない。**参考画像内の地形防御・回避補正は再現しない**（現行合意は地形・高さの戦闘補正なし）。

## 絵を作る手段と実行時構成

- **オフラインで高品質に描く**: 背景を高品質画像から分離し、地面・手前の遮蔽物・キャラクター・光／エフェクト・HUDを別素材にする。
- **ランタイムは軽量に**: 固定視点を活かし、描画済み地形を基本とし、論理マス／高さ／通行可否は別データで管理。
- スクリーンショットを丸ごと背景にすると、焼き込まれたキャラクターや射程が残り、インタラクションに破綻が出る。**一枚絵の貼り込みを完成扱いしない**。
- リリアなどのキャラクターは基準素材・統一制作フローを設け、スプライト差分でidentityを保つ。
- Unity採用時はOrthographic camera＋URP＋SpriteRenderer／Canvas／必要最小限のMeshを基本とする。初期実装は静的な小マップ・少数ユニットで検証。
- Unity WebはiOS Safariをサポートするが、起動サイズ・メモリ／フレームレートに注意して実機で評価する。

## 先行する3つの成果物

### G01-A: 見栄えの基準スクリーン（機能は限定）
同じ9:16端末サイズで、地形・リリア・敵・HP・HUD・範囲表示を参考画像と並べて比較。  
**合格条件**: 美麗さ・キャラクターの見え方・グリッドの視認性について、静止画比較で改善箇所を明確にできる。

### G01-B: 操作可能な小規模戦場
固定カメラ、移動・射程、敵タップ情報、移動先選択、攻撃・HP変化、ピンチ拡大・ドラッグスクロール。  
**合格条件**: 見た目を維持しながらiPhone上でタップ誤認がなく操作できる。

### G01-C: P05.4機能の統合
経験値・固定成長・フェイズ進行・敵AI・3つの勝利条件を移植／統合。  
**合格条件**: 既存P05.4でできた主要行動が失われず、一章をクリアできる。
