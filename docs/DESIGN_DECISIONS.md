# 銀花戦記 — 設計判断の正本（Design Decisions）

> **現在有効な設計判断の唯一の正本**。最終更新：2026-10-19／版：v1.0（初期集約）。
>
> 本書は「なぜ、何を守るか／まだ何を決めていないか」を扱う。実装そのもの、試験結果、素材の出自・承認状態は各専門資料の正本を参照する。過去の議論や試作上の選択を、自動的に確定仕様へ昇格させない。

## 0. 運用ルールと文書体系

### 0.1 判断の状態

- **確定**：ユーザーの明示的な採用・方向転換に基づく。変更する場合は本書に新判断と理由を追記。
- **方向性確定**：目的・設計原則は採用済みだが、具体手段は検証で変更可能。
- **暫定／実装済み**：現在動いている・試用している。ユーザーの最終承認とは限らない。
- **未決**：選択肢、仮説、評価条件を記す。エージェントは試作上の暫定値を明示してよいが、恒久的に確定しない。
- **旧方針（履歴）**：現在は採用しない判断。理由と後継判断を示す。

### 0.2 所有範囲・優先順位

| 情報の種類 | 正本 | 更新方針 |
| --- | --- | --- |
| **設計原則・決定・未決論点・優先順位** | **本書 `docs/DESIGN_DECISIONS.md`** | 決定や判断変更のたびに更新 |
| 戦闘の現在の実装挙動・操作・起動手順 | `battle-pc/README.md` および `battle-pc/src/` | 実装変更に追従。理念・未決事項を重複定義しない |

| **アセット単位の採否・版・出自・配置値** | `battle-pc/assets/manifest.json` | 承認は明示されたものだけ。コード側の採用と承認を区別 |

## 1. ゲーム全体の目的

### D-001：作品の中心体験【確定】

『銀花戦記』は、女性キャラクターを主軸とする王道ファンタジーのタクティクスSLG。**戦術 × 固定成長による育成 × キャラクターへの愛着 × 物語・交流**を統合する。参照する戦術と育成の基本像は『ファイアーエムブレム』系列。システムを複雑化するより、少数のルールの相互作用を重視する。

### D-002：美術・世界観【確定】

白銀、淡い青を基調とした涼やかで清らかなファンタジー。美しい自然、石造建築、花、光と影を重視する。可憐・上品・凛々しい女性キャラクターが物語の中心。**幻想が幻想である所以以外の人体・重心・接地・布・光・空間には高いリアリティを求める**。最終的な合否は人間が見た自然さ・美しさで評価する。フォトリアル化やフル3D化それ自体を目的にしない。

### D-003：キャラクターと物語【方向性確定】

リリアは仲間思いで優しく、凛々しく勇敢で親しみやすいヒロイン。女性キャラクター自身の友情、愛情、勇気、成長を描く。複数キャラクターの視点や章ごとの焦点移動を許容。街での日常的な交流を大切にする。『ドラゴンナイト4』の人間関係、意外な展開、伏線と再解釈、街探索が創作上の参照点。

**未決**：プレイヤーの物語上の視点、寡黙な男性司令官／幼馴染／恋愛導入の扱い、親密度の数値化とゲーム作用、二周目・伏線回収の構造。主人公／恋愛の最終構図を今回の戦闘試作だけで確定しない。

## 2. 戦術と成長のルール

### D-004：少数ルールの戦術【確定】

- 味方フェイズ→敵フェイズの交代制。味方内は**素早さ順**に行動。
- 菱形グリッド。地形は基本的に通行可否のみを管理し、**地形・高低差・向きによる攻撃、防御、回避の補正は設けない**。
- 高さは **0 / 1 / 2**。隣接したマス間の高さ差が1以内なら上り下りを許容（実装済み仕様）。遮断地形・占有マスの通行は不可。
- **固定方向の浅い2.5D視点**。カメラ回転・俯瞰モード・別視点への切り替えで情報を読ませる設計は採用しない。
- マウスで選択、移動、攻撃、待機を直感的に行える。HP・現在の行動者・移動／攻撃範囲は理解しやすく表示。
- 参考画像中の「草地回避+10%」等はビジュアルの仮表示に過ぎず、ルールとして**採用しない**。

### D-005：固定成長とEXP【確定＋一部実装済み】

- 成長量はキャラクター固有の固定表で決め、成長確率ガチャにしない。
- 通常攻撃と撃破でEXPを区別。現行B01では攻撃+10・撃破+30・EXP100でレベルアップ（**現在の実装値**）。
- 防御・回復などへのEXP付与は**将来の方向性**。未実装の仕様を実装済みと呼ばない。
- 経験値の手動配分と編成選択は当面不要。キャラクター増加時に再検討。

### D-006：上位職【方向性確定／詳細未決】

レベル到達に連動するクラスチェンジ。基本クラスの延長にある上位職とし、変化に至る出来事・会話・後日談で成長を物語化する。

**未決**：昇格レベル、各人の職、分岐有無、成長補正、シナリオ条件。

### D-007：章・勝利条件【暫定／試作実装】

現行の敵全滅、拠点制圧、NPC護衛は試作済み。各章に何を使うか、章進行や敗北・勝利後の保存は今後検討。章全体・長期キャンペーンは未完成。

## 3. プラットフォーム／画面

### D-008：PCファーストへ転換【確定：旧9:16スマホ前提を廃止】

- **PC向け横長**を第一設計対象とする。主基準 **19:9（例1900×900）**、16:9やウルトラワイドへ適応。
- マウス主操作（ホバー、クリック、ドラッグ、ホイール）。キーボードは補助。マウスだけで基本操作を完了できること。
- 広い戦場を表示してもキャラクターの魅力と識別性を損なわない大きさを確保する。
- PC化しても**カメラ方向は固定**。平行移動・ズームは許容するが、回転／視点切り替えは導入しない。
- 旧スマホ9:16のP05.4・街探索HTMLは資産として残す。今後の新規PC画面に旧レイアウトを強制しない。

**履歴**：当初はスマホ9:16で企画。2026-10-18にPCファーストへ転換。G01に混在する16:9基準は旧段階の記録であり、現在の主基準は19:9。

### D-009：戦場ビジュアル【方向性確定】

基準は石橋・清流・花・草地・立体的な段差・白銀系の遺跡や遠景が美しい戦場の参考画像。縦長参考からPC横長モックへ再構成し、**表示マップを少し広げながらキャラの大きさを十分確保する**意図を採用。

- 背景・前景遮蔽・ユニット・グリッド・移動／攻撃範囲・HP・HUD・演出は独立レイヤーに分離。
- 画像内に可変のキャラやHPやUIを焼き込んで一枚絵を操作する「疑似実装」は完成扱いしない。
- 高低差0/1/2・地形通行可否を**論理マップ**で管理。美術上の段差・川・橋と実際のマス座標を一致させる。
- ユニットの足元アンカー、地面の影、奥行き順、手前遮蔽を重視する。
- 戦術盤面として**使える広さ**と美術背景として見える広さは区別する。現行B01は元の8×10の論理マップを発展させたもの。

## 4. UIに関する判断と未決論点

### D-010：UIの基本原則【確定】

1. **戦場が主役**。HUD・装飾で重要なユニットや移動先を隠さない。
2. 情報を読むために視点回転を要求しない。
3. その場の戦術判断に必要なHP・範囲・位置・行動者を速く理解できる。
4. 世界観の美しさを維持しつつ、文字・範囲・敵味方を視認可能にする。
5. 装飾画像と実際の入力・情報ロジックを分離する。
6. 機能を増やす前に、誤操作しやすい根本的な操作体系を安定させる。

### D-011：現在のPC HUD【**実装済みだが暫定**】

現行B01：上部＝章・ターン、左＝味方一覧・素早さ順、右＝勝利条件・敵情報、中央＝菱形戦場、下＝選択者情報と行動コマンド、左下＝地形情報、右下＝ズーム／カメラ復帰。主要操作は**移動、攻撃、敵の範囲、待機**（過去の参考モックの「能力」と同一ではない）。

現在の二段階確認（クリックで経路／攻撃予測→再クリックで確定）、行動者を示すUI、必要時の自動カメラ平行移動は実装済み。**これらを全て最終仕様として固定したわけではない**。PR #3では視認性等の改善を行った。

### D-012：先へ進むためのUI品質ゲート【**提案・未確定**】

- **P0（次工程へ進む前に是正）**：操作不能、誤ターゲット／誤移動、移動可否・地形／論理座標の重大な不一致、重要HPや範囲の欠落。
- **P1（早期是正）**：HUDによる遮蔽、キャラや陣営・現在行動者の識別困難、頻繁な意図しないカメラ移動、文字の読みにくさ。
- **P2（並行改善）**：余白・装飾・微妙なフォントや色の調整、地形境界の小さな美術差異。
- **P3（将来）**：高度な歩行・斬撃・待機アニメーションや追加の豪華演出。

**判断仮説**：UIの「見た目の最終完成」を待つより、操作体系・情報構造・盤面可読性を先に安定させ、以後は他工程と並行改善する。この品質ゲートの採用は実プレイで評価してから決める。

## 5. キャラクターとアート素材

### D-013：生成AI主体の素材制作【確定】

- GPT画像生成を背景・人物・衣装・装飾・エフェクトの主な制作手段とする。
- ゲーム実行環境は高品質な**生成済み素材を軽量に合成・描画**し、入力・戦闘処理を担当する。
- アセットの制作・確認・切り出し・透過・サイズ／アンカー／メタデータ登録をエージェントが扱えること。
- **人物同一性（identity）重視**。承認済みデザインを基準に参照付き生成・編集・差分を作る。新たに生成した人物を承認なしに正本へ昇格しない。
- 正確な日本語テキスト、HP・数値・クリック領域はコードで管理する。

**既存素材との整合注意**：現在の `manifest.json` にある新規生成人物は `candidate-unreviewed`。旧P05.4由来のリリア画像を基準参照として抽出した記録はあるが、リリアの全身キャラクターシートなどの承認済み原本が全てGitHubにあるとは限らない。確認せず「同一デザイン保証」としない。

**リリアの意図した造形**：銀髪系、清楚で可憐、白銀系甲冑・淡青系衣装。脚は足甲冑・ニーハイを避け、素足とショートブーツのデザインを基準とする。現在の生成アトラスのプロンプト中には黒のサイハイブーツという不整合があり、**現行候補素材の未承認差分としてレビューが必要**。

## 6. 開発技術・エージェント

### D-014：技術は目的に従属する【確定】

Unity採用は目的ではない。重要なのは**参考画像に近い美しい戦闘を速く遊べること**、既存資産を活かせること、エージェントがAPI・MCP・ブラウザ検証を通じて「実装→表示→撮影→比較→修正」を反復できること。

**現行実装**はPixiJS v8 + TypeScript + Vite + HTML/CSS HUD + GitHub Actions / Pages + Playwright。P05.4の戦闘ロジックを `battle-pc/src/core.ts` に型付き移植。現行を理由なく別エンジンへ移植しない。

### D-015：エージェントの開発運用【方向性確定】

- 意図・制約・評価条件は人間が定義。実装方針・検証・反証はエージェントが提案・実行。
- 基本想定は**Codexクラウド＋sol6.1＋利用可能な画像生成スキル**。
- 現行B01は開発報告上Windowsローカルで実装・検証。希望環境と実際の実行環境を混同しない。
- ソースはGitHubで追跡可能にし、必要な変更はPR・検証証跡・実画面スクリーンショットを伴う。
- リファレンスは見栄えの基準、**実画面**を最終的な検証対象とする。
- 完了報告には未達・未測定・未承認事項を明示。別の作品や新機能を際限なく付け加えない。

## 7. 街探索とゲーム全体の未決事項

## 8. 次の開発判断

### 現段階の主要な問い【未決】

> **UIのどこまでを固めてから、マップ規模拡張・戦闘演出・章進行・物語へ進むか。**

**推奨する仮説**：UIの操作意味・情報階層・マップとの対応を安定させる。「全ての細部が美しい」ことは継続改善に任せ、先へ進む。**ただし、この仮説そのものはユーザーの最終決定ではない。**

次の候補：

- **A. UI基礎品質の合格判定**：UI-01〜UI-09をプレイ検証しP0/P1を整理。
- **B. 論理戦場の拡張**：背景だけではないプレイ可能マスを広げ、戦術性を検証。
- **C. 人物の動作／接地感**：静止・歩行・攻撃の自然さとidentity維持。
- **D. 章進行と長期育成**：セーブ、勝利後、次章、クラスチェンジへ接続。
- **E. 街と物語の統合**：交流からキャラクターへの愛着を発展。

### 次の判断の前に観察すべきこと

戦場での選択・移動・攻撃・敵情報・視点復帰を実際に試し、**誤選択・読めない文字・隠れたターゲット・視点の意図しない移動・論理マップと絵の不一致**を列挙する。それがP0/P1かP2/P3かを分類し、次に進む判断材料とする。
