P05.4を基にした独立したPC向けプレイアブル版です。既存の `../index.html` と `../town/index.html` は変更していません。基準は今回の依頼に従い **19:9（1900×900）**。16:9・ウルトラワイドにも適応します。

## 起動

Node.js 20.19以上（検証: 24.19）、npmを使用します。

```powershell
cd C:\Projects\ginka-senki\battle-pc
npm ci
npm run dev -- --port 4173
```

http://127.0.0.1:4173/ をPCブラウザで開きます。`file://`でHTMLを直接開く方式には対応しません。

```sh
npm run build
npx vite preview --host 127.0.0.1 --port 4174
```

製品ビルドは `dist/` です。相対URLでビルドするため、サブディレクトリにも配置できます。公開URLは **https://sugikazu777.github.io/ginka-senki/battle-pc/** です。`main` 更新時にGitHub Actionsがテスト・ビルド・Pages公開を実行します。既存のトップページと街版も同じサイトに保持するため、勝利画面の「街へ」リンクから移動できます。

## 操作

- 味方は **フィオナ → リリア → ミレイユ → セレス** の素早さ順に行動。顔アイコンまたはユニットを選択すると情報を表示。行動順外の味方は閲覧のみ。
- 青い移動先をクリックして金色の経路を確認し、再クリックで移動。前後左右、移動力以内、1段差まで。川・岩・占有マスは通行不可。
- 「攻撃」で射程を赤く表示。敵をクリックすると予測ダメージを表示し、再クリックで攻撃。敵の情報はホバーでも表示。
- 移動後に攻撃、または「待機」。全員が行動すると敵AIが順番に移動・攻撃し、次ラウンドへ。
- ホイールでズーム、ドラッグでスクロール。「視点を戻す」で初期表示。回転・視点切替なし。
- M 移動 / A 攻撃 / D 敵範囲 / W 待機 / Esc 経路と敵情報の取消。
- 右上で敵全滅・拠点制圧・護衛を選択。変更すると戦闘を初期化。メニューに説明と再開ボタン。

## 既存仕様の再利用

`src/core.ts` は P05.4 の `makeTiles`、ユニット能力、BFS移動、マンハッタン射程、`threats`、ダメージ式、固定成長表、EXP、敵AI評価式、フェイズ、勝敗判定を分離・型付けしたものです。

- ダメージは `max(1, atk - def)`。地形・高さ・向きによる戦闘補正なし。
- 攻撃EXP 10 / 撃破EXP 30 / 100でレベルアップ。固定成長表を保持。
- リリアが倒れると敗北。敵全滅、リリアによる拠点到達、護衛使節の目的地到達を保持。
- 味方4人と敵3人の名前・能力・射程を保持。使節は護衛時のみ追加。
- 広いPC構図に合わせて味方初期配置を変更。元の8×10マップを基に、背景上の川・外周に対応する7マスを追加で通行不可に設定。
- 旧版ではクリックで味方の行動順を変更できましたが、今回は依頼の「味方内は素早さ順」を厳密に適用しています。
- 旧リリア画像をidentity基準に利用。旧石材・壁テクスチャとアフィン投影処理を北側の高さ2のテラスに再利用。草・水テクスチャも来歴保存として抽出しています。

## 表示構成

PixiJS v8 / TypeScript / Vite。固定した画角のワールドをパン・ズームします。

1. 人物・文字・グリッドのない生成背景
2. 独立した高さ2の石材テラス、地形高さマーカー
3. 論理マスと一致する菱形グリッド
4. 青い移動・赤い射程・金色の経路
5. 足元の影、奥行き順の透明ユニット
6. 各ユニットの独立したHPバー・数値
7. 生成斬撃・光輪、ダメージ数値、花びら
8. HTMLの日本語HUD、情報パネル、コマンド

地形は背景美術＋明示的な論理グリッドで管理します。移動・攻撃に応じて人物、HP、範囲、エフェクトが更新され、背景への焼き込みではありません。足元アンカー、セル中心、ヒット判定、アニメーションは共通投影を使用しています。

## 素材管理

`assets/manifest.json` に用途、参照元、生成日、プロンプト要約、解像度、alpha、SHA-256、切り出し座標、表示サイズとアンカーを記録しています。生成は **組み込み image_gen** を使用。APIキーや外部の生成サービスは使っていません。

新規生成は背景1枚、人物アトラス1枚（8人）、UI/VFXアトラス1枚（4素材）。人物と装飾は透明PNGから無劣化切り出しを行い、元アトラスも保持しています。新素材はレビュー待ちの実装候補であり、ユーザー承認済みの正本とは区別しています。人物の歩行は同じスプライトを経路に沿って移動し、軽い上下動を加えることでidentityを維持します。

## 検証

```sh
npm test
npm run build
npx playwright install chromium
# 別ターミナルで上記のvite previewを起動
# PowerShell:
$env:BATTLE_URL='http://127.0.0.1:4174/?debug=1'
npm run test:browser
```

- `tests/core.test.ts`: 元HTMLの関数を読み込み、同じ盤面・ユニット状態で移動範囲、射程、脅威範囲、敵AIの結果を比較。他に行動順、障害物、段差、二重移動、弓の最小射程、ダメージ、EXP、成長、全勝利条件、敗北条件、護衛進行を検証。
- `tests/browser.mjs`: マウスで選択・経路確認・移動・攻撃・待機し、敵AIフェイズと勝利画面まで通しプレイ。ズーム・ドラッグ・作戦切替・再開・説明、4画面サイズも検証。
- `?debug=1` は検証用の **読み取り専用** snapshotのみ公開。テストはユニット位置・HP・ターンを直接変更しません。
- 通しテストにはHMRの影響を避けるため製品ビルドを推奨します。

結果と実画面は `evidence/`、詳細は `VALIDATION.md` を参照してください。

## G02 地形診断デモ

開発サーバーを起動し、`http://127.0.0.1:4173/?g02=1` を開くと地形診断モードになります。診断中は戦闘が一時停止し、診断パネルからグリッド・座標ラベル・足元マーカー・透明度を操作できます。「診断を終了して戦闘へ戻る」で診断前の同じ状態に戻ります。通常プレイでは診断パネルは表示されません。

```sh
npm run dev -- --port 4173
npm run test:g02
```

確認手順と所見は [`docs/G02_SPATIAL_DIAGNOSTICS.md`](../docs/G02_SPATIAL_DIAGNOSTICS.md) に記録しています。

## 残課題・範囲

- 実行・検証は、このチャットに接続されたWindowsローカル環境。クラウド環境への移設とsol6.1指定実行は行っていません。
- 生成背景の小さな花・壁・橋の欄干とセル境界は、全画素で一致する地形メッシュではありません。独立した手前遮蔽物マスクの追加、花際の細部の調整が今後の美術課題です。
- 歩行・攻撃の専用描き下ろしコマ、音声・BGM・セーブ、章をまたぐ成長保存は未実装。P05.4同様、再開始で成長はリセットします。
- この戦場で4味方・3敵。参考画像の5人目を新しい戦闘職として追加せず、護衛使節としてのみ用意しました。
- UIはPCを対象。狭いスマホ縦画面は保証しません。日本語Webフォントが取得できない場合はシステムフォントにフォールバックします。
